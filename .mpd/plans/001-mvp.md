# MailCollect MVP 计划

> 契约文档。任何成员实现前先读 `docs/requirements.md` 与 `packages/shared/src/*`。
> 本文件冻结接口与验收标准；改动契约必须由 captain 提交。

## 架构（三层，单向依赖）

```
packages/shared   ← 纯类型 + Zod schema（无运行时依赖，无 IO）
packages/core     ← 业务逻辑：mail 适配器 / pipeline / llm / store / sync
apps/server       ← Hono HTTP+SSE，唯一对外接口，持有 token 鉴权
apps/desktop      ← Electron 外壳：起本地服务 + 开窗口
apps/ui           ← React 19 + Vite + dhtmlx-gantt，只认 HTTP/SSE
```

依赖方向：`shared ← core ← server ← desktop`，`ui → shared(types only)`。禁止反向依赖。

## 数据流

```
IMAP/POP3/Graph --raw--> store.raw_email
        |
        v
  pipeline: strip quotes -> thread assemble -> broadcast gate (代码) -> LLM extract -> time resolve
        |
        v
  store.task (status=candidate/confirmed/dismissed) --change_log--> sync seam
        |
        v
  GET /api/tasks -> UI 待办卡片 / 甘特图
```

## 冻结点（不可由成员单方修改）

1. `packages/shared/src/domain.ts` — 领域类型
2. `packages/shared/src/extraction.ts` — LLM 输出 Zod schema
3. `packages/shared/src/api.ts` — HTTP 路由与载荷
4. `packages/core/src/mail/types.ts` — `MailSource` 接口
5. `packages/core/src/llm/port.ts` — `LlmPort` 接口
6. `packages/core/src/store/schema.sql` — 表结构

## 风险

| 风险 | 缓解 |
|---|---|
| DeepSeek json 模式返回空白 | 视作可重试；改用 strict tool call |
| IMAP 服务商限流/断连 | 指数退避 + 单账号串行队列 |
| Electron 原生模块 ABI | 服务端优先用 `node:sqlite`，不引入原生依赖 |
| dhtmlx Community 无 deadline 元素 | 用自定义 task layer 画到期标记 |
| 时区/DST 错判 | 只信 chrono-node + IANA 时区，不信模型算日期 |

## 已知缺口（v1 交付后处理）

1. **Graph 设备码登录不可达**（Explorer 已核实）：`createMailSource(account)` 只有单参，
   Graph 分支 `new GraphMailSource(account)` 不传 `options.onDeviceCode`；
   `GraphMailSource` 也没有 `lastDeviceCodeNotice` getter（该 getter 只在
   `MsalDeviceCodeAuth` 上，而 `#auth` 是私有的）。后果：用 Graph 账号点"验证"会静默挂起。
   修法（小改）：给 `createMailSource` 加可选第二参透传，并给 `GraphMailSource` 补 getter；
   服务端再加 `POST /api/accounts/:id/login` + SSE `device-code` 事件。
   当前建议：**先用 IMAP 适配器**，Graph 账号等这个修完再开。
2. `core/src/index.ts` 未 re-export `pipeline` 与 `mail` 的具体实现，只导出 `mail/types`。
   服务端应按子路径导入（`@mailcollect/core/mail`、`/pipeline`），已如此实现。
3. `MailSourceFactory` 仍是单参形状；上面第 1 条修完后应一并放宽。
